## 编码问题修复（UTF-8双重编码）

### 根因
MySQL 8.0 默认 `character_set_client=latin1`，导致 JDBC 连接写入中文时双重编码（UTF-8 bytes → Latin-1 → UTF-8）。

### 修复措施
1. **MySQL 服务器配置** `/opt/homebrew/etc/my.cnf`：添加 `[client]`/`[mysql]`/`[mysqld]` 的 `default-character-set=utf8mb4` 和 `character-set-server=utf8mb4`
2. **JDBC URL** `application.yml`：添加 `connectionCollation=utf8mb4_unicode_ci`
3. **Spring 配置**：添加 `spring.http.encoding.charset=UTF-8` + `WebMvcConfig.java`（Jackson 输出 UTF-8）
4. **数据修复**：所有损坏的中文数据（t_room, t_user, t_role, t_permission, t_department）通过 DELETE + INSERT 重新写入

### 教训
- MySQL 8.0 brew 安装默认不配置 charset，必须手动设置
- `CONVERT(CAST(CONVERT(col USING latin1) AS BINARY) USING utf8mb4)` 可能导致数据损坏（变成 `?`），最可靠的方式是 DELETE + INSERT

## 前端 API 响应解包 Bug

### 问题
`api.ts` 响应拦截器 `return response.data` 已解包一层，但所有页面用 `res.data.code` 访问，导致 `undefined === 200`，登录无反应。

### 修复
- 全部 14 个页面组件：`res.data.code` → `res.code`，`res.data.data` → `res.data`
- 全部 7 个 service 文件：移除泛型类型参数，改为 `as Promise<any>`
