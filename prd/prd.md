# PRD: 自习座位预约系统

## 1. 项目概述

### 背景
高校自习室座位利用率低，存在"一座难求"与"占座不用"并存的问题。学校希望通过信息技术手段提升座位利用率和周转率。

### 目标
- 实现座位在线预约、签到、违约管理的完整流程
- 提供管理员 RBAC 权限管理
- 提供学生端智能助手（自然语言查询座位）
- 提升座位利用率和周转率

### 目标用户
| 角色 | 说明 |
|---|---|
| 学生 | 预约座位、签到、查看预约/历史、使用智能助手（含院系属性，用于自习室权限隔离） |
| 管理员（多角色） | 管理自习室/座位、查看预约/违约记录、调整系统参数 |

## 3. 功能需求

### 3.1 核心业务功能

#### F001 自习室管理
- **描述：** 管理员对自习室的 CRUD 及可用性维护
- **属性：** 自习室名称、位置、所属院系（可为空=全校共享）、开放时间（开始/结束，默认 07:00-22:00）、状态（开放/关闭）
- **规则：** 属于院系的自习室仅对该院系学生可见；关闭后已有预约需处理（通知+取消）；管理员可临时调整单日开放时间
- **验收标准：** 管理员可完成登记/修改/注销/启停；学生端仅看到有权限且开放的自习室

#### F002 座位管理
- **描述：** 管理员对自习室内座位的 CRUD 及可用性维护
- **属性：** 座位编号（自习室内唯一）、所属自习室、行列位置、插座类型（无/固定插座/移动导轨插座）、位置标记（靠窗/靠走廊/中间）、状态（可用/停用）
- **规则：** 座位编号在自习室内唯一；停用后不可预约但保留历史记录
- **验收标准：** 管理员可完成登记/修改/注销/启停；座位图正确反映状态

#### F003 座位预约
- **描述：** 学生选择自习室、座位、时间段进行预约
- **规则：**
  - 以整点小时为单位（如 8:00-10:00）
  - 单次最多预约 4 小时（系统参数可调 `max_reservation_hours`）
  - 同一时段同一座位不可重复预约
  - 学生同一时段不可预约多个座位
  - 院系自习室权限校验
- **取消与违约规则：**
  - 预约开始前取消：释放座位，不记违约
  - 预约开始后、超时15min之前取消：释放座位，不记违约
  - 超时15min未签到：系统自动取消 + 记录违约，此时不可手动取消
- **验收标准：** 预约成功后状态为"待签到"；超限/冲突时提示；取消规则正确执行

#### F004 签到
- **描述：** 学生通过 Web 端输入教室动态编码完成签到
- **规则：**
  - 每个教室每天生成一个动态编码（与教室+日期关联）
  - 编码在教室屏幕上展示
  - 签到时间窗口：预约开始前 15 分钟 ~ 预约结束时间
  - 学生在签到时间窗口内输入编码签到
  - 签到成功后预约状态变为"使用中"
- **验收标准：** 输入正确编码签到成功；错误编码提示失败；超出时间窗口不可签到

#### F005 预约生命周期与提醒
- **描述：** 预约的状态流转及消息推送
- **状态流转：**
  ```
  待签到 → (签到) → 使用中 → (到时) → 已完成
  待签到 → (超时15min未签到) → 已取消(违约)
  待签到/使用中 → (学生/管理员取消) → 已取消
  ```
- **推送规则：**
  - 预约时间前 15 分钟：提醒即将开始
  - 预约时间后 10 分钟未签到：催促签到
  - 预约时间后 15 分钟未签到：取消预约 + 记录违约 + 通知学生
- **推送方式：** 邮件（兜底）+ WebSocket（页面内实时推送），双通道。用户在线时 WebSocket 优先；离线时邮件兜底，WebSocket 消息不丢失
- **验收标准：** 三个时间节点均触发推送；超时取消后座位释放

#### F006 违约管理
- **描述：** 记录学生违约行为
- **规则：**
  - 超时未签到自动记录违约（类型：超时未签到）
  - 违约记录含：学生、预约信息、时间、类型
  - 管理员可查看违约记录
  - 学生可查看自己的违约记录
- **验收标准：** 违约自动记录；双方可查看

#### F007 座位搜索
- **描述：** 学生多条件搜索可用座位
- **搜索条件：** 自习室、日期、时间段、插座类型（无/有插座）、位置标记（靠窗/靠走廊/中间）、院系
- **结果展示：** 座位编号、可用时段、所属自习室、插座标记、位置标记
- **验收标准：** 多条件组合搜索返回正确结果

#### F008 预约历史与再次预约
- **描述：** 学生查看历史预约并快速再次预约
- **规则：** 历史列表展示完整预约记录；"再次预约"以当前日期+同时段发起预约（如可用）
- **验收标准：** 可查看历史；可一键再次预约

#### F009 动态编码生成与展示
- **描述：** 系统为每个教室每天生成动态编码，供签到使用
- **规则：** 编码与教室+日期绑定；每日更新；管理端/教室屏幕可查看当日编码
- **验收标准：** 编码生成正确；每日不同

### 3.2 RBAC 权限管理

#### F010 角色管理
- **描述：** 管理端角色的增删改
- **默认角色：**
  - `super_admin`：全部权限
  - `room_admin`：自习室/座位管理、查看预约记录
  - `service_admin`：查看预约/违约记录、代客预约/取消
  - `viewer`：仅查看预约/违约记录
- **验收标准：** 角色可自定义增删改

#### F011 权限定义
- **描述：** 功能权限的细粒度控制
- **权限项：**

| 权限编码 | 说明 |
|---|---|
| `reservation:view` | 查看预约记录 |
| `violation:view` | 查看违约记录 |
| `reservation:manage` | 为用户预约和取消预约 |
| `seat:manage` | 座位登记和注销 |
| `room:manage` | 自习室登记和注销 |
| `system:config` | 调整系统参数 |
| `role:manage` | 角色和权限管理 |
| `user:manage` | 用户角色分配 |

- **验收标准：** 每个角色仅可访问其权限范围内的功能；管理界面按权限展示菜单

#### F012 用户-角色分配
- **描述：** 给用户分配角色
- **规则：** 一个用户可有多个角色（权限取并集）
- **验收标准：** 管理员可给用户分配/移除角色

### 3.3 智能助手

#### F013 智能聊天助手
- **描述：** 学生端自然语言交互入口
- **能力：**
  - 查询可用座位（"今晚有空座吗？"）
  - 条件搜索（"帮我找靠窗/有插座的座位"）
  - 查询自己的预约（"我今天定了哪"）
  - 取消预约（"取消我今晚的预约"）
- **实现：** 接入大语言模型 API，将用户意图映射为系统查询/操作
- **验收标准：** 输入自然语言，返回结构化座位信息或执行操作

### 3.4 系统参数管理

#### F014 系统参数
- **描述：** 可配置的系统参数
- **参数表：**

| 参数名 | 默认值 | 说明 |
|---|---|---|
| `max_reservation_hours` | 4 | 单次最大预约小时数 |
| `check_in_remind_before_min` | 15 | 签到提前提醒（分钟） |
| `check_in_warn_after_min` | 10 | 签到逾期警告（分钟） |
| `check_in_cancel_after_min` | 15 | 签到逾期取消（分钟） |

- **验收标准：** 管理员可修改参数，修改即时生效

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 列表接口响应 < 500ms；座位图加载 < 1s；WebSocket 消息延迟 < 3s |
| 安全 | JWT 认证；RBAC 鉴权；防止越权操作 |
| 兼容性 | 学生端/管理端均支持 Chrome/Firefox/Safari 最新2个版本 |
| 可用性 | 签到提醒和超时取消需准时执行（定时任务） |
| 可扩展 | 推送通道预留扩展点；智能助手可替换 LLM 提供商 |
| 座位图 | 静态布局图，美观、大方、整洁，由管理员配置行列后固定展示 |

## 7. 技术方案

| 层 | 技术栈 |
|---|---|
| 前端（学生端） | React + TypeScript |
| 前端（管理端） | React + TypeScript |
| 后端 | Java 21 + Spring Boot 3 + MyBatis Plus |
| 数据库 | MySQL 8.0 |
| 认证 | JWT (Spring Security) |
| 定时任务 | Spring @Scheduled + 线程池（避免大量提醒延迟） |
| 智能助手 | 接入 LLM API（使用 openclaw.json 中配置的 API key） |
| 推送 | 邮件 (JavaMail / SMTP) + WebSocket (Spring WebSocket + STOMP) |

### 编码规范

- 后端分层：Controller → Service → Repository(MyBatis Plus) → Mapper → Request(DTO) → Response(VO)
- 数据库外键禁止在 DB 层面设定，由后端业务层面约束
- 接口 RESTful 风格，统一响应格式 `{ code, message, data }`

| feature/US-S08 | 作为学生，我想搜索座位（按自习室、时间段、插座、靠窗/靠走廊等条件），以便快速找到合适座位 | 支持多条件组合搜索，结果含座位编号、可用时间、教室、插座标记、位置标记 |
| feature/US-S09 | 作为学生，我想查看预约历史并快速再次预约同一座位，以便重复使用喜欢的座位 | 历史列表含座位信息，一键再次预约（如该时段可用） |
| feature/US-S10 | 作为学生，我想查看自己的违约记录，以便了解自己的信用情况 | 违约列表含时间、座位、原因 |
| feature/US-S11 | 作为学生，我想通过自然语言与智能助手对话来查询和预约座位，以便更便捷地操作 | 支持自然语言输入，返回结构化座位信息或执行预约操作 |
